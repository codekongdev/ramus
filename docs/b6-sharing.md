# B6 · 결론을 다른 대화에 보내기

작업 모달의 저장된 결론에서 **다른 대화에 보내기**를 누르면 같은 모달 안에서 대화 검색으로 전환한다. 현재 프로젝트의 다른 대화를 제목으로 검색하고 여러 대화를 선택한다. 같은 이름의 대화는 상위 경로로 구분한다. 선택한 대화는 칩으로 해제할 수 있으며, 전송 후에는 원래 결론 보기로 돌아간다.

받은 대화의 오른쪽 **공유받은 결과**에서 고정된 결론 버전을 읽거나 다른 대화에 다시 보낼 수 있다. 열기·닫기는 입력을 변경하지 않는다. 원본에 새 버전이 생기면 표시만 갱신하며, 보내는 사람이 다시 보내야 입력 버전이 바뀐다. 결과로 새 대화를 만드는 기능은 B7 범위다.

## 저장·권한·실행

- `POST /api/result-revisions/{id}/shares`: 저장된 결과 버전을 최대 20개 대상에 보낸다. 모든 대상의 접근 권한과 프로젝트를 검사한 뒤 `Share` 이력과 `ConversationInput` 스냅샷을 같은 트랜잭션에 기록한다. 빈 목록, 중복 대상, 원본 대화, 다른 프로젝트 대상은 거부한다.
- `GET /api/conversations/{id}/inputs`: 해당 대화에 고정된 입력과 원본 최신 버전 번호를 반환한다. 본문·제목·출처는 전송한 버전의 스냅샷을 유지한다.
- 동일 버전 재전송은 `unchanged`, 새 버전은 `replaced`, 이미 더 새 버전이 연결된 대화에 이전 버전을 보내면 `kept_newer`를 반환한다. 동시 전송도 버전을 낮추지 않는다.
- 변경 요청은 기존 `Idempotency-Key` 계약을 따른다. 재시도에서도 현재 접근 권한을 확인하며, 같은 동작의 네트워크 재시도는 같은 키를 사용한다.
- 입력이 바뀐 대화에 커밋 후 `conversation_inputs.updated`를 발행한다. 수신 화면은 이벤트와 재접속 시 다시 조회한다. `result.updated`는 새 버전 표시를 갱신한다.
- 전송 자체는 메시지나 AI 실행을 만들지 않는다. 이후 대상 대화에서 `@AI`를 요청하면 기존 `SqlReceivedConclusionSource`와 컨텍스트 조립기가 고정된 결론을 입력으로 사용한다.

기존 테이블과 OpenAPI 계약을 사용하므로 추가 마이그레이션은 없다. 백엔드는 sharing 모듈의 유스케이스·포트·저장 어댑터로 분리하고, 결과·대화 조회는 각 모듈의 공개 인터페이스를 사용한다. 화면은 기능별 MVI와 기존 디자인 시스템을 따른다.

## 로컬 검증

```sh
pnpm verify
pnpm --filter @ramus/web build
pnpm test:e2e tests/e2e/sharing.spec.ts tests/e2e/results.spec.ts
```

통합·브라우저 테스트는 임시 PostgreSQL 데이터베이스를 만들고 정리한다. 브라우저 테스트는 실제 API와 worker에 `FakeLLM`을 주입하며, 실제 모델이나 메일 서비스를 호출하지 않는다. 실제 키를 사용한 모델 응답 품질과 배포 환경은 이 검증에 포함하지 않는다.
