# ramus 상위 기획

## 핵심 문제 정의

각자 AI로 한 작업을 팀에서 함께 검토하거나 이어 쓰려면, 사용자가 내용과 사용 방식을 따로 전달하고 적용해야 한다.

## 1. 서비스와 핵심 사용자

- **서비스 이름과 한 줄 소개:**  
  **ramus — 팀원과 AI가 함께 논의하고, 일을 나눠 수행하고, 결과를 이어 쓰는 협업 공간.**

- **가장 먼저 이 서비스를 필요로 할 사람은 누구인지:**  
  **팀원들이 각자 AI를 사용하는 제품팀에서, 공동 기획과 업무 분담을 이끄는 PM·서비스 기획자.**  
  동료가 만든 스킬을 공유하고, AI로 조사한 내용을 함께 검토하고, 결과를 다음 담당자에게 넘기는 일을 반복하는 사람이다.

## 2. 사용자가 겪는 구체적인 상황

- **사용자는 어떤 일을 하려는 중인지:**  
  팀원들이 각자 AI로 멤버십 기능을 조사했다. 이제 조사 결과를 함께 검토하고, 회원 등급·혜택·반품 정책을 정해 하나의 기획서로 만들려 한다.

- **어느 순간에 막히거나 불편을 겪는지:**  
  **개인 AI에서 한 작업을 다른 사람과 함께 검토하거나, 다른 사람의 AI 작업에 사용하려는 순간이다.**

  예를 들어 A가 AI와 정리한 등급 정책을 B가 이어서 검토하려면, A는 검토할 내용을 B에게 공유해야 한다. B는 그 내용을 자기 AI에 제공하고 질문하거나, A에게 후속 질문을 대신 입력해 달라고 해야 한다.

  A가 사용한 조사 스킬까지 같은 방식으로 쓰려면, 스킬도 전달받아 적용해야 한다.

- **그 문제가 얼마나 자주 발생하고, 해결하지 못하면 무엇을 잃는지:**  
  동료의 스킬을 쓰거나, 개인 AI의 답변을 함께 검토하거나, 다른 사람의 결과로 다음 작업을 시작할 때 발생한다.  
  그때마다 **내용을 공유하고, 자기 AI에 적용하거나 다시 입력하는 작업**이 추가된다. 각자 독립적으로 끝내는 업무에는 이 문제가 없다.

## 3. 지금 사용하는 해결 방법

- **현재는 어떤 도구나 방식으로 해결하는지:**

  | 하고 싶은 일 | 해결 방식 |
  |---|---|
  | 동료가 만든 스킬 사용 | 메신저로 스킬 파일과 사용법을 받아 자기 AI에 적용한다. |
  | AI 답변 공동 검토 | 답변을 복사하거나 링크로 공유한다. 화면을 공유하고 한 사람이 질문을 대신 입력하기도 한다. |
  | 역할을 나눠 실행 | 담당을 정하고 각자 사용하는 AI에 자료와 요청을 따로 넣는다. |
  | 결과를 받아 다음 작업 시작 | 전달받은 결과를 자기 AI에 제공하고 후속 작업을 요청한다. |

- **그 과정에서 여전히 남는 어려움은 무엇인지:**  
  **공유한 내용을 읽는 것과, 그 내용을 AI 작업에 사용하는 것이 별도 행동이다.**

  메신저에서 결과를 받았더라도 자기 AI에 가져가야 하고, 스킬 파일을 받았더라도 적용해야 한다. 한 사람의 개인 AI 대화를 함께 검토할 때는 후속 질문을 그 사람이 대신 입력하거나, 다른 사람이 내용을 가져가 별도로 질문해야 한다.

  기존 AI 제품에도 공통 자료·지침을 활용하거나 프로젝트를 팀에 공유하는 기능이 있다. ramus는 **스킬 적용, 공동 질문, 작업 분담, 결과 재사용을 하나의 작업 흐름으로 제공한다.** [ChatGPT 공식 문서](https://learn.chatgpt.com/docs/projects), [Claude 공식 문서](https://support.claude.com/en/articles/9517075-what-are-projects)

## 4. 핵심 기능과 사용 흐름

- **가장 중요한 기능은 무엇인지:**  
  **팀에서 함께 사용할 스킬·자료·결과를 선택하고, 이를 바탕으로 사람과 AI가 작업을 이어가는 기능.**

  | 기능 | 사용자가 하는 일 |
  |---|---|
  | 공통 스킬·자료 | 프로젝트에 등록된 업무 방식과 자료를 선택해 적용한다. |
  | 공동 대화 | 같은 대화에서 팀원들이 의견을 내고 AI에 직접 질문한다. |
  | 작업 분담·실행 | 독립적으로 진행할 분석을 나눠 맡기고 진행 상태를 확인한다. |
  | 결과 정리·인계 | 검토한 결과를 저장하고 다른 대화의 AI 입력으로 사용한다. |

- **사용자가 무엇을 입력하거나 행동하는지:**  
  ① 멤버십 기획서와 참고 자료, 공통 조사 스킬을 선택한다.  
  ② 팀원들과 기획서를 검토하고 AI에 질문한다.  
  ③ 경쟁사 조사와 예외 상황 검토를 별도 작업으로 맡긴다.  
  ④ 담당자가 각 결과를 읽고 보완한 뒤 저장한다.  
  ⑤ 저장한 결과를 통합 기획 대화에서 사용한다.  
  ⑥ 합의한 기획 결과를 선택해 화면·정책별 상세 기획을 시작한다.

- **서비스가 무엇을 처리하는지:**  
  선택한 자료와 지침을 AI에 제공한다. 독립적으로 수행할 수 있는 분석은 별도 작업으로 나누고 진행 상태를 표시한다.

  작업 대화에서 결론·근거·남은 질문을 정리한다. 사람이 검토해 저장한 결과는 버전과 함께 보관하고, 다른 대화에서 AI의 참고 자료로 선택할 수 있게 한다.

  **개인 대화는 비공개로 유지하고, 사용자가 공동 작업에 제공한 자료·지침·결과만 함께 사용한다.**

- **최종적으로 어떤 결과를 제공하는지:**  
  **팀이 검토한 멤버십 구성안과, 이를 입력으로 사용하는 상세 기획 대화.**

  구성안에는 고객 흐름, 회원 등급, 혜택, 반품 등 예외 처리, 아직 정하지 않은 항목이 담긴다. 화면·정책 담당자는 이 구성안을 선택해 각자의 상세 기획을 시작한다.

## 5. 좋은 결과의 기준

- **어떤 결과가 나오면 사용자가 “잘 해결됐다”고 느끼는지:**  
  **다른 사람이 검토한 결과를 선택해, 내용을 다시 옮겨 적지 않고 자기 AI 작업을 시작할 수 있을 때.**

  예를 들어 화면 담당자가 멤버십 구성안을 선택하고 “이 정책을 기준으로 마이페이지를 설계해줘”라고 요청할 수 있어야 한다. 필요한 정책이 빠져 있다면, 무엇이 빠졌는지도 확인할 수 있어야 한다.

- **그 결과에서 꼭 확인할 수 있어야 하는 내용은 무엇인지:**

  | 확인할 내용 | 멤버십 기획에서의 예 |
  |---|---|
  | 작업에 사용한 자료 | 어떤 기획서·경쟁사 자료·스킬을 참고했는가? |
  | 검토한 결론 | 회원 등급과 혜택을 어떤 방식으로 구성하기로 했는가? |
  | 결론의 근거 | 경쟁사에서 확인한 사실인지, AI 제안인지, 팀의 결정인지 |
  | 남은 질문 | 반품으로 등급이 내려가면 이미 받은 쿠폰은 어떻게 처리하는가? |
  | 사용할 결과 버전 | 상세 기획이 어떤 버전의 구성안을 기준으로 시작됐는가? |

  **AI 실행 완료와 사람의 검토 완료는 구분한다.** AI가 답변을 마쳤다는 이유만으로 팀의 결정으로 취급하지 않는다.

## 6. 사용자의 변화와 궁극적인 가치

- **사용 전과 후에 무엇이 달라지는지:**  
  사용 전에는 동료가 보낸 스킬과 결과를 받아 자기 AI에 따로 적용한다. 함께 답변을 검토할 때는 한 사람이 질문을 대신 입력한다.  
  ramus에서는 프로젝트에 등록된 스킬을 선택하고, 같은 대화에서 팀원과 AI에 질문하고, 저장된 결과를 다음 AI 작업의 자료로 선택한다.

- **그 덕분에 사용자가 새롭게 할 수 있게 되는 일은 무엇인지:**  
  동료가 AI와 진행한 작업에 질문을 보태거나, 그 결과를 선택해 자기 작업을 시작할 수 있다.  
  팀은 함께 검토할 때는 같은 대화에서 일하고, 역할을 나눌 때는 별도 작업으로 진행한 뒤, 필요한 결과를 다시 모아 사용할 수 있다.

- **그 변화가 사용자에게 왜 중요한지:**  
  **개인 AI의 작업을 팀에서 이어 쓰기 위해 내용을 따로 옮기고 설정하는 단계를 줄일 수 있기 때문이다.**  
  ramus가 필요한 지점은 각자의 작업이 만나는 순간이다.

## 7. 가장 기억에 남았으면 하는 것

- **서비스의 가치가 가장 잘 드러나는 사용 사례 하나:**  
  **“각자 AI로 조사한 멤버십 자료를 함께 검토하고, 추가 분석을 나눠 수행한 뒤, 같은 구성안으로 상세 기획을 시작한다.”**

  | 구간 | 90초 영상에서 보여줄 장면 |
  |---|---|
  | 0–15초 | A가 조사 결과와 스킬 파일을 보낸다. B는 이를 자기 AI에 넣고 후속 질문을 입력한다. |
  | 15–30초 | ramus에서 공통 스킬과 조사 결과를 선택한다. A와 B가 같은 대화에서 AI에 직접 질문한다. |
  | 30–50초 | 경쟁사 비교와 반품 예외 검토를 별도 작업으로 진행한다. 팀은 그동안 출시 범위를 논의한다. |
  | 50–70초 | 담당자가 결과를 검토·저장한다. 통합 대화에서 두 결과를 사용해 멤버십 구성안을 정리한다. |
  | 70–90초 | 화면·정책 담당자가 같은 구성안을 선택해 상세 기획을 시작한다. |

- **영상을 본 사람이 기억했으면 하는 한 문장:**  
  **“각자 AI로 한 일을, 팀이 함께 검토하고 이어 쓰는 곳. ramus.”**
