# B1 공통 스킬·자료 화면

WF-10·14, F-08·09, AC-16의 최초 등록·검색·적용 흐름이다. 기존 B1 API와 `origin/b/B1-resources-ui`의 화면 초안을 현재 워크스페이스에 통합했다. 기능 구현은 `apps/web/src/features/resources/`에 있고, `WorkspacePage`의 메뉴 슬롯에서 연다. 새 API·이벤트·DB 스키마는 추가하지 않는다.

## 사용 흐름

1. 왼쪽 **스킬·자료** 메뉴를 연다. 대화가 없어도 프로젝트 자원을 검색·등록할 수 있다.
2. **스킬 등록**에서 이름·설명·지침을 작성하거나 **SKILL.md 불러오기**로 채운다. `.md`·`.txt` UTF-8 텍스트만 허용하며, 이름·지침이 비면 등록을 막는다. 파일 읽기 실패 시 입력은 유지한다. 불러오기는 입력을 채우며 저장은 등록 버튼으로 진행한다.
3. 등록하면 v1이 생성되고 같은 모달의 목록으로 돌아온다. 열린 대화가 있으면 새 버전을 선택 칩에 추가한다. 등록만으로 대화에 적용하지 않는다.
4. 이름·설명으로 검색하고 선택한 버전을 확인한다. 현재 적용 버전과 최신 버전이 다르면 함께 표시하며, 최신 버전 선택은 별도 버튼으로 한다.
5. **적용**을 누르면 정확한 버전 ID 목록을 현재 대화에 저장하고 모달을 닫는다. 실패하면 검색어·선택을 유지하며 동일한 요청은 같은 멱등 키로 재시도한다.

목록·등록은 하나의 Dialog에서 전환한다. 뒤로가기는 등록 초안을 버린다. 적용 목록을 처음 읽는 동안 선택을 잠그며, 등록이 먼저 끝나도 기존에 적용한 버전을 보존한다. 파일 읽기 요청 번호로 이전 파일·폐기한 폼의 늦은 결과를 무시한다. 프로젝트의 공유 SSE 연결로 자원·적용 변경을 받고, 재접속 시 목록을 다시 읽으면서 편집 중인 선택·초안을 보존한다.

## 검증

```sh
pnpm verify
pnpm --filter @ramus/web build
pnpm test:e2e tests/e2e/resources.spec.ts
```

Reducer 테스트는 버전 고정·멱등 재시도·파일 응답 순서와 등록/적용의 동시 동작을 확인한다. UI 테스트는 공유 SSE·재접속·지연된 적용 조회를, 경계 테스트는 잘못된 API 성공 응답을 확인한다. E2E는 실제 API와 임시 PostgreSQL DB에서 등록·파일 입력·이름/설명 검색·v1 유지·명시적 v2 적용·실패 후 재시도를 검증한다. 실제 AI나 메일 서비스는 호출하지 않는다.

E2E 실행 시 `artifacts/b1-register-1440.png`, `artifacts/b1-versions-1440.png`에 화면을 저장한다. 자원의 상세·이력·수정 화면은 B2 작업이다.

2026-11-09 검증 결과: `pnpm verify` 9단계 PASS, FAIL·SKIP 0(웹 372개, API 단위 573개·통합 182개), 프로덕션 빌드 통과. B1 E2E 3개와 대화 E2E 1개, 작업 모달 E2E 3개가 통과했다. 작업 모달 E2E는 기존 하네스에 맞춰 별도의 Vite 서버와 `RAMUS_WEB_PORT`를 지정했다. 1440px 등록·목록 스크린샷도 확인했다. 실제 AI 호출과 B2 UI는 이번 검증 범위에 포함하지 않는다.
