# B2 공통 자료 버전 관리

B1 스킬·자료 목록에서 **상세·버전 이력**을 열어 선택한 버전의 내용·작성자·저장 시각을 확인한다. 목록·상세·수정은 같은 모달의 본문을 전환하며, 목록으로 돌아오면 검색어와 선택한 버전을 유지한다. 이 브랜치는 B1 화면 구현(`10ce5e4`)을 기반으로 한다.

**수정**은 서버에서 최신 버전을 읽은 뒤 그 버전 ID를 기준으로 시작한다. 새 버전 저장에 성공하면 상세에서 저장한 버전을 보여준다. 저장은 프로젝트 자료만 갱신하며 현재 대화의 선택 버전·다른 대화·분기된 자식·실행 중 입력 스냅샷을 바꾸지 않는다. 상세에서 **현재 대화에 적용**을 눌러야 해당 대화의 버전 설정이 바뀐다. 과거 버전도 같은 방법으로 적용할 수 있으며 프로젝트의 최신 버전은 유지된다.

## 충돌과 재시도

- 다른 참여자가 먼저 저장하면 `VERSION_CONFLICT`를 표시하고 입력 초안을 유지한다. **최신 버전 확인**에서 새 내용을 읽은 후 **초안으로 돌아가기**로 입력을 다시 볼 수 있다. 기준 버전을 자동으로 바꾸거나 병합하지 않는다.
- 저장 응답이 유실돼도 같은 본문은 같은 `Idempotency-Key`로 재시도한다. 저장된 버전의 응답을 재사용해 중복 버전을 만들지 않는다.
- 저장·적용 중에는 중복 전송과 모달 닫기를 차단한다. 실패 후에는 입력과 선택을 유지한다.
- 자료 읽기·파일 읽기는 요청 번호와 취소 신호로 늦게 도착한 결과를 무시한다. `.md`·`.txt` UTF-8 파일만 허용한다.
- 파일 교체에 실패하면 새 버전 저장을 막는다. 유효한 파일을 다시 선택하거나 편집을 취소해야 오류가 해제된다.

## 구현 경계

`revisionModel`·`revisionReducer`·`revisionEffects`·`ResourceRevisionStep`이 상세/이력/수정을 담당한다. 순수 Reducer가 화면 상태와 고정된 기준 버전을 관리하고 EffectHandler가 기존 OpenAPI 자원 API를 호출한다. 부모 `resourcesReducer`가 현재 선택 목록의 해당 자원만 교체해 적용하므로 다른 자료의 선택은 유지한다. API 응답은 생성된 타입을 기준으로 경계에서 검증한다. 작성자 이름은 프로젝트 참여자 조회로 연결하며 조회할 수 없으면 계정 ID를 보여준다.

기존 B2 API에 추가한 권한 검사는 멤버십이 회수된 뒤 멱등 receipt의 이전 응답을 다시 읽는 것을 막는다. 최초 작업의 트랜잭션 내부 검사도 유지한다. API 계약·DB 스키마·공유 멱등 실행기 인터페이스는 변경하지 않는다.

## 검증 명령

```sh
pnpm verify
pnpm --filter @ramus/web build
pnpm exec playwright test tests/e2e/resources.spec.ts tests/e2e/resource-revisions.spec.ts
```

백엔드 통합 테스트는 매번 임시 PostgreSQL DB를 만들어 과거 버전 보존, 동시 저장 충돌, 멱등 재전송, 권한 회수, 부모·자식·Run의 버전 고정을 확인한다. 브라우저 테스트는 두 계정의 저장/적용 분리, 과거 버전 적용, 충돌 초안, 응답 유실 후 재시도, 좁은 화면과 키보드 조작을 확인한다. 실제 메일·모델 서비스를 호출하지 않는다. 화면 캡처는 `artifacts/b2-*.png`에 저장한다.
