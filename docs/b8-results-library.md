# B8 결과물 목록

왼쪽 **결과물** 메뉴에서 현재 프로젝트의 저장된 결론을 제목·출처 대화·최신 버전·저장 시각으로 조회한다. 저장 시각이 최신인 결론부터 표시한다. 목록은 조회 전용이며 다중 선택·결론 저장·보내기·새 대화 만들기를 제공하지 않는다(F-08·WF-09·AC-14).

`GET /api/projects/{project_id}/results`는 로그인과 프로젝트 멤버십을 확인한다. 프로젝트의 결과와 최신 승인 revision을 연결해 읽으므로 생성 중·검토 중·실패한 초안은 목록에 나오지 않는다. 이미 저장된 결과에 새 초안이 생겨도 목록에는 기존 승인 제목·버전·저장 시각이 유지된다. 출처 대화 제목은 대화 모듈의 조회 포트를 통해 읽는다. 기존 OpenAPI 응답 계약과 DB 스키마는 유지한다.

화면은 `features/results-library`의 State·Intent·Reducer·EffectHandler·View로 구성한다. 생성된 OpenAPI 타입에 맞춰 응답을 검증하고, 승인 버전이 없는 행이나 잘못된 시각은 오류로 처리한다. 빈 목록·조회 중·오류 재시도를 구분한다. 결과 변경 이벤트와 SSE 연결 복구 시 목록을 다시 읽고, 요청 취소와 요청 번호로 늦은 응답이 최신 상태를 덮지 않게 한다. 프로젝트가 바뀌면 기존 모달과 요청을 폐기한다.

결과물 모달은 공용 Dialog와 기존 디자인 시스템을 사용한다. 뒤의 대화·입력 초안·주소를 유지하며, Escape나 닫기로 돌아오면 메뉴 버튼에 포커스를 돌려준다. 긴 제목과 출처는 좁은 화면에서 줄바꿈한다.

## 검증

```sh
pnpm verify
pnpm --filter @ramus/web build
pnpm exec playwright test tests/e2e/results-library.spec.ts tests/e2e/results.spec.ts tests/e2e/resources.spec.ts tests/e2e/projects.spec.ts tests/e2e/sharing.spec.ts
```

API 통합 검사는 초안 제외·승인 head 유지·저장 시각 정렬·프로젝트 격리·멤버십 회수를 확인한다. 프런트 단위 검사는 응답 검증·요청 순서·취소·오류를 확인한다. 브라우저 검사는 실제 서버에서 초안 제외와 v1/v2 저장 반영, SSE 재접속, 새로고침과 프로젝트 전환, 대화 초안 보존, GET 전용 조회를 확인한다. 오류·잘못된 응답 재시도와 390px 모달·키보드 포커스도 확인한다. 화면 캡처는 `artifacts/b8-results-library-*.png`에 저장한다.

2026-11-09 검증: `pnpm verify` PASS 9·FAIL 0·SKIP 0(웹 445개, API 단위 620개·통합 249개), 프로덕션 빌드, 위 브라우저 시나리오 12개가 통과했다. 1440px·390px 캡처도 확인했다. 독립 코드 검수에서 차단 결함은 발견되지 않았다.

같은 날 B6가 병합된 최신 `main`(`507f5de`)으로 rebase한 뒤 `pnpm verify` 9단계(웹 454개, API 단위 622개·통합 262개), 프로덕션 빌드, B6를 포함한 브라우저 시나리오 13개를 모두 통과했다. README·API 구현 목록·WorkspacePage 충돌은 B6와 B8을 모두 보존해 해결했으며 독립 검수에서도 회귀 결함은 발견되지 않았다. SSE 검사는 실제 EventSource에 전송 오류를 주입해 연결을 닫고, 실제 재연결·서버 재조회로 놓친 v2 저장을 복구하는 경로를 확인한다.

DB 검증은 임시 `ramus_test_*` DB를 사용하고 정리한다. 메일과 모델은 테스트 어댑터를 사용한다. 실제 메일·모델 서비스 호출과 배포는 검증 범위에 포함하지 않는다.
