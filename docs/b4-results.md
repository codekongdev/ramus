# B4 결과 정리와 버전

`b/B4-results`는 `main`의 `c91b75d`에서 만든 별도 워크트리다. 기존 `ramus-setup`의 진행 중인 변경은 포함하지 않는다.

최초 구현은 PR #24로 병합되었다. 추가 검수 보완은 `b/B4-summary-hardening`에서 병합된 B4와 A8을 포함한 `origin/main` 기준으로 분리했다.

작업이 준비되면 모달 헤더의 **결과 정리**로 별도 summary 실행을 등록한다. 결과 탭에서 생성된 결론을 검토·수정해 v1으로 저장하고, 승인 결론 수정 또는 **다시 정리**로 후속 버전을 만든다. 본문은 `conclusion` 하나이며 출처와 입력 버전은 별도 메타데이터다. 정리 중 모달을 닫아도 실행은 계속되고, 실패해도 승인 버전과 작업의 ready 상태는 유지된다.

주요 변경은 다음과 같다.

- `modules/results/`: 정리 등록·조회·승인 UseCase, SQL 저장소, summary handler와 순수 프롬프트, 권한 및 이벤트 처리.
- `modules/conversations/*/summary_inputs.py`, `modules/execution/*/summary_tasks.py`: 상대 모듈 테이블에 직접 접근하지 않는 조회 인터페이스.
- `modules/execution/*/task_queries.py`: 작업 큐·모달 진입에 필요한 인증된 Task 조회. 중단·재시도 API는 별도 작업 범위다.
- `modules/execution/infrastructure/summary_gateway.py`, `main.py`: 계정의 자격증명으로 실행하는 OpenAI Responses 어댑터와 기본 worker 조립. 모델 응답은 스키마로 검증하고 provider 오류·키 원문은 노출하지 않는다. 어댑터는 [공식 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)를 기준으로 작성했다.
- `features/results/`, `WorkspacePage.tsx`, `TaskModal.tsx`: 결과 탭 MVI, 연결 확인, 초안 편집·저장·이력, 재연결 조회, 충돌 비교 및 복구.
- `contracts/openapi.json`, 생성된 웹 타입, `docs/contracts.md` v1.7: 승인 저장의 필수 `source_run_id`와 긴 정리 한도 실패 코드 추가. 같은 승인 버전에서 초안만 재생성되어도 과거 편집 본문을 새 출처로 저장하지 않게 한다.

마이그레이션 `c84f15b694e2`는 `result_draft.context_snapshot`을 추가한다. 정리를 요청할 때 메시지 범위와 자료·결론 버전 내용을 고정하고 worker가 그 입력을 사용한다. 재정리는 이전 승인 결론과 그 이후 메시지를 사용한다. 승인 저장은 기준 버전의 조건부 변경과 불변 버전 추가를 같은 트랜잭션에서 처리한다.

저장 충돌이나 SSE 갱신은 편집 중인 본문과 기준 출처를 자동으로 덮지 않는다. 최신 승인 결론 또는 새로 정리된 초안을 비교한 뒤 사용자가 명시적으로 편집 기준을 갱신할 수 있다. 네트워크 오류 후 같은 저장을 재시도할 때는 같은 멱등 키를 사용한다.

추가 검수에서 정리·승인 응답의 멱등 재전송이 현재 참여 권한을 확인하지 않는 문제를 발견해 수정했다. 신규 처리의 트랜잭션 내부 권한 검사와 별도로, 저장된 응답을 반환하기 전에도 접근 권한을 확인한다. 두 API 모두 참여 권한 제거 전에는 동일 응답을 재전송하고, 제거 후에는 404를 반환하는 통합 테스트로 검증한다.

긴 원문은 결과 모듈의 `LongSummaryGateway`가 레코드별로 나눠 핵심을 추출한 뒤 결론 본문 하나로 종합한다. 순수 분할 코어가 각 조각에 메시지 순번·자료 버전·문자 범위를 보존하며, 모든 호출이 같은 요청자·입력 스냅샷을 사용한다. 일반 업무 실행과 짧은 정리는 기존 게이트웨이에 그대로 전달한다. 기본 한도는 모델 요청당 UTF-8 입력 48KiB, 전체 원문 1MiB, 모델 호출 64회, 종합 4단계이며 추출 동시성은 2다. 원문·호출·종합 한도 초과는 `SUMMARY_LIMIT_EXCEEDED`로 표시하고 기존 승인 버전을 보존한다. 중간 출력도 스키마와 크기를 검증하며 전체 실행 제한 시간과 취소가 계속 적용된다. 실제 모델의 요약 품질과 지연 시간은 별도 확인이 필요하다.

검증은 PostgreSQL의 임시 테스트 DB와 FakeLLM 또는 메모리 HTTP 전송으로 실행했다. 개발·공유 DB를 초기화하거나 실제 AI를 호출하지 않았다.

- 최신 원격 main 반영 후 `pnpm verify` 9개 검사 모두 통과(실패·생략 없음). API 단위 테스트 612개와 통합 테스트 203개, 총 815개 통과.
- 웹 전체 테스트 341개 통과. 결과 기능 단위 테스트 20개를 포함한다.
- 보완 후 브라우저 B4 시나리오 5개 통과: v1/v2와 실패 보존, 승인 충돌과 SSE 초안 보존, 재생성 출처 충돌 복구, AI 연결 취소·재개, 실제 서버 저장·재조회.
- 긴 정리 단위 테스트 18개는 다중바이트 원문 완전 복원, 요청별 예산, 출처·계정 유지, 단계별 종합, 한도·출력 오류·취소를 검증한다. 실제 worker 통합 테스트는 긴 정리 성공과 한도 초과 시 기존 승인본 보존도 확인한다.
- API 정적 검사, OpenAPI·생성 타입 계약 검사, 웹 타입 검사·프로덕션 빌드·한글 문구 검사 통과. Alembic head는 `c84f15b694e2` 하나다.

후속 B5 결론 보기의 보내기·새 대화 액션, B6·B7·B8, 실제 키를 사용한 수동 모델 검증은 이 작업에 포함하지 않는다.

## 2026-11-10 정리 지침 누락 보완

[실제 모델 점검](password-auth.md#실제-모델-확인)에서 정리 출력의 표식 누락이 관측됐다. 정리 프롬프트가 스킬의 `instructions`까지 일반 참고 데이터로 취급하고, 긴 정리의 종합 단계에는 부분 결론만 전달하는 문제를 보완했다.

- 적용한 고정 버전의 `skill.instructions`를 정리 작업 지침으로 명시한다. 필수 문구·표식·조건을 결론 본문에 반영하고 출력 전 누락을 확인하도록 한다. 시스템 규칙과 `conclusion` 출력 스키마가 우선한다.
- 긴 정리는 추출·중간 종합·최종 종합의 모든 호출에 동일한 고정 스킬 지침과 버전 ID를 원본으로 전달한다. 부분 결론에서 지침이 빠져도 종합 단계가 원본을 다시 참조할 수 있다.
- 지침 원문은 사용자 역할의 JSON에 두며 시스템 메시지로 승격하지 않는다. 파일·텍스트·대화·이전 결론·부분 결론은 참고 데이터로 유지한다. 반복 전달하는 지침도 요청 크기 한도에 포함하고, 한도를 넘으면 자르거나 생략하지 않고 `SUMMARY_LIMIT_EXCEEDED`로 실패한다.

검증: `pnpm verify --only api:lint,api:unit` 통과(API 단위 740개), `uv run --project apps/api pytest apps/api/tests/test_results_integration.py -q` 통과(임시 PostgreSQL DB 통합 12개). 부분 결론이 표식을 생략한 다단계 종합에서도 원본 지침이 모든 호출에 도달하는지, 과대 지침이 모델 호출 전에 실패하는지, 정리 요청 뒤 적용 버전을 v2로 바꿔도 v1을 사용하는지 확인했다.

이 검증은 모델 포트에 전달하는 입력과 worker·저장 흐름을 확인한다. 실제 모델 재호출과 장문 출력의 지침 준수 품질 평가는 수행하지 않았다.
