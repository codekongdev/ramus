# B9 공동 샘플 준비와 리셋

명시적인 준비 CLI가 ‘쇼핑몰 멤버십 도입 · 공동 체험’과 ‘멤버십 상세 기획 · 후속 체험’을 구성한다. 모든 쇼핑몰 정보와 수치는 가상 예시다. ‘멤버십 기능 설계’에는 팀장 과제만 두고 등급·실적·혜택·예외에 대한 통합 정책은 아직 확정하지 않는다.

## 준비 명령

작업할 데이터베이스를 루트 `.env`의 `DATABASE_URL`에 지정하고 마이그레이션을 적용한 뒤 실행한다.

```sh
uv run --project apps/api python -m ramus_api.modules.seed
```

출력 형식은 기존 명령과 같이 `project_id` 하나를 포함한 JSON이다.

```json
{"project_id": "52ca4f3a-7913-510c-9e52-064b3f1db1a4"}
```

빈 데이터베이스에 준비하는 항목은 다음과 같다. 이후 실제 사용자가 작성한 데이터는 이 수에 포함하지 않는다.

| 항목 | 초기 구성 |
| --- | --- |
| 프로젝트 | 공동 과제와 후속 상세 기획 대상, 총 2개 |
| 예시 작성자 | 예시·팀장, 예시·조사 담당 A·B·C, 총 4명 |
| 대화·메시지 | 설계 과제 1개와 A·B·C 조사 3개, 총 4개 대화·10개 메시지 |
| 공통 자원 | 벤치마킹 스킬, 조사 항목, 가상 서비스 기본 정보, 각 v1 |
| 과거 완료 이력 | 예시 조사 Task 3개는 `ready`, Run 4개는 `succeeded` |
| 저장 결론 | A·B·C 조사 결론 각 v1, 총 3개 |
| 설계 입력 | 조사 결론을 설계 대화에 보내 둔 Share 3개와 버전 고정 입력 3개 |

조사 메시지와 결론은 고객 흐름·등급·실적·혜택·예외를 같은 기준으로 비교하며 확인되지 않은 정책을 구분한다. 메시지의 예시 작성자 표시와 결론 저장자의 예시 계정으로 실제 사용자 작업과 구분한다. 준비 명령은 모델을 호출하지 않고 현재 실행 중인 것처럼 `pending`·`running` 작업을 만들지 않는다.

## 재실행과 로그인 보존

고정 시드 키에서 UUIDv5를 만들고 기존 프로젝트 마커와 별개인 콘텐츠 마커 v1을 기록한다. 같은 데이터베이스에서 동시에 준비하거나 다시 실행해도 같은 콘텐츠를 중복 생성하지 않고, 사용자가 바꾼 프로젝트 이름과 실제 메시지·자료·결과를 보존한다. 콘텐츠 버전이 달라졌다고 기존 작업을 자동으로 덮어쓰지 않는다.

로그인은 준비된 샘플 프로젝트의 편집 참여 관계만 조회·추가한다. 준비 전에는 기본 공동 프로젝트만 보장하고 후속 프로젝트나 콘텐츠를 만들지 않는다. 예시 콘텐츠의 생성·초기화는 로그인, 새로고침, 재접속과 분리되어 있다. 준비 전에 로그인한 계정과 이후 참여한 계정도 동일한 프로젝트를 사용하며 계정별 콘텐츠 복제본은 만들지 않는다. 준비와 로그인이 겹쳐도 같은 트랜잭션 잠금으로 참여 등록 순서를 맞춰 후속 프로젝트 권한을 빠뜨리지 않는다.

## 운영자 리셋

리셋 권한의 경계는 서버·데이터베이스에 접근할 수 있는 운영자 CLI다. 일반 참여자를 위한 HTTP 리셋 API나 제품 버튼은 제공하지 않는다.

먼저 API와 worker를 중단하고 기존 작업의 보존 필요성을 확인한다. 필요한 작업을 백업한 뒤, 두 고정 프로젝트의 사용자 작업까지 삭제해도 되는 경우에만 다음 명령을 실행한다.

```sh
uv run --project apps/api python -m ramus_api.modules.seed --reset \
  --confirm-project-id 52ca4f3a-7913-510c-9e52-064b3f1db1a4 --work-preserved
```

세 인자 `--reset`, 정확한 `--confirm-project-id`, `--work-preserved`를 함께 제공해야 한다. `--work-preserved`는 기존 작업을 백업했거나 삭제해도 된다는 운영자의 확인이다.

리셋은 두 고정 프로젝트 안의 대화·메시지·자료·작업·실행·저장 결과·공유 입력을 지우고 초기 예시를 다시 구성한다. 실제 사용자가 두 프로젝트에서 만든 작업도 삭제 범위에 포함된다. 계정·세션·개인 AI 연결·참여 관계·프로젝트 이름과 다른 프로젝트의 작업은 보존한다.

`pending`·`running` 실행이 있거나 데이터베이스 사용과 잠금이 충돌하면 리셋을 거부한다. 다른 프로젝트가 샘플의 결론을 참조하는 경우에도 해당 프로젝트를 지우지 않고 리셋을 거부한다. 거부 또는 중간 오류는 트랜잭션 전체를 롤백하며 부분 초기화를 남기지 않는다. 정상적인 준비 명령은 이러한 전체 초기화를 수행하지 않는다.

## 검증 범위

단위·통합 검증 명령:

```sh
uv run --project apps/api ruff check apps/api
uv run --project apps/api pytest apps/api/tests/test_seed_content.py
uv run --project apps/api pytest apps/api/tests -k 'seed or sample_project_access'
```

통합 테스트는 `conftest.py`가 생성·마이그레이션·삭제하는 `ramus_test_*` 임시 데이터베이스만 사용한다. 준비 명령의 동시 실행, 재실행과 로그인 뒤 보존, 예시 연결 관계, 운영자 리셋의 확인 인자·실행 중 거부·다른 프로젝트 참조와 롤백을 검증한다. 테스트는 실제 모델이나 메일 서비스를 호출하지 않는다.

저장된 예시 결론은 B4의 결과·버전 조회 API에서 확인한다. 결론 보내기·후속 대화 생성·결과물 목록을 포함한 전체 제품 시연 E2E는 B5~B8 통합 이후에 남아 있다.
