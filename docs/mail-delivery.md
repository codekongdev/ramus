# 운영 메일러와 발송 재시도

2026-11-10 · BL-02·BL-03 구현. 실제 메일 공급자 계정 연결과 발송은 별도 운영 확인으로 남긴다.

## 설정과 조립

`main.build_container`가 `build_mailer`를 호출한다. 개발·테스트 기본값은 `LoggingMailer`, SMTP는 `SmtpMailer`이며 기존 `Mailer` 포트와 테스트 주입을 유지한다.

운영 설정은 `.env.example`의 `RAMUS_ENV`, `RAMUS_MAILER`, `RAMUS_SMTP_*`, `RAMUS_AUTH_SECRET`를 사용한다. staging·production에서 logging mailer, 호스트·발신 주소 누락, 불완전한 인증 쌍, 프로세스 임시 인증 비밀값을 거부한다. TLS 또는 STARTTLS의 인증서·호스트를 검증한 뒤 인증·발송하며 평문 SMTP 모드는 없다. 발송자가 승인한 주소와 공급자의 계정 설정은 운영자가 지정한다.

네트워크 I/O는 스레드로 분리한다. 시간 제한은 각 소켓 동작에 적용되며 전체 발송 시간 상한은 아니다. 취소된 요청의 SMTP 스레드가 뒤늦게 발송을 마칠 수 있다. 서버가 메일을 수락한 이후 QUIT·close 실패는 수락 성공을 뒤집지 않는다. 공급자 응답·비밀번호·메일 본문은 오류나 로그로 내보내지 않는다.

## 발송 상태와 복구

1. 기존 멱등 executor의 짧은 DB 트랜잭션에서 `email_code_delivery` 예약을 만들고 receipt에는 `delivery_id`만 남긴다.
2. 이메일 advisory lock 아래 `sending` 시도를 점유한다. 이메일별 발송은 하나이며, 시도 토큰·2분 lease와 코드 해시만 저장한다.
3. 트랜잭션을 닫은 뒤 메일을 보낸다.
4. 성공한 시도 토큰이 여전히 현재 시도이면 코드 해시를 `email_code`에 활성화하고 `sent`로 바꾼다. 60초 재발송 대기는 이 확정 시점부터 시작한다. 성공 receipt 재생은 추가 메일 없이 같은 시각을 돌려준다.
5. 확인된 발송 실패는 해당 시도를 `failed`로 바꾸고 503 `SERVICE_UNAVAILABLE`를 반환한다. 같은 키 또는 새 키로 즉시 재시도할 수 있으며 시간당 이메일·IP 요청 상한은 유지한다.

전송 중이거나 실패한 새 코드가 이전 정상 코드를 가리지 않는다. 요청 취소·서버 중단은 미발송으로 확정할 수 없으므로 lease를 유지하고 만료 후 새 시도·새 코드로 재점유한다. 늦은 이전 성공·실패는 시도 토큰으로 무시한다. 실패한 오래된 행동 이후 새 발송이 이미 성공했다면 오래된 키는 422 `AUTH_CODE_EXPIRED`로 거부한다.

SMTP와 DB는 하나의 트랜잭션에 참여하지 않으므로 중단 구간에서 메일이 추가로 갈 수 있다. 자동 발송 worker 대신 클라이언트의 같은 키 재요청으로 복구한다. 운영에서 `RAMUS_AUTH_SECRET`를 바꾸면 기존 코드 검증도 무효화되므로 고정해야 한다.

마이그레이션 `d65a18c9f203`은 발송 상태 테이블과 이메일별 sending 부분 고유 인덱스를 만든다. downgrade는 기존 코드 해시를 보존하고 신규 발송 포인터 receipt만 제거해 이전 앱의 응답 재생과 호환한다. 일반 개발·공유 DB에는 이번 작업에서 마이그레이션을 실행하지 않았다.

## 검증과 남은 확인

SMTP 단위 검사는 실제 네트워크 없이 TLS·인증 순서, 주소·헤더 검증, 시간 제한, 수락 후 정리 실패와 예외 비노출을 확인한다. API 통합 검사는 임시 PostgreSQL에서 즉시 재시도·중복·경합·기존 코드 보존·lease 재점유·늦은 완료·시간당 상한과 평문 비저장을 확인한다. 브라우저 검사는 503 뒤 이메일·멱등 키를 보존하고 대기 없이 다시 요청해 로그인하는 흐름을 확인한다.

최종 검증: `pnpm verify` 9단계 모두 통과(웹 499개, API 단위 707개·DB 통합 307개 포함), 실패·건너뜀 없음. `pnpm test:e2e` 전체 40개 통과. `git diff --check`와 E2E 서버 Ruff도 통과했다. API 통합에는 마이그레이션 upgrade·check·downgrade·재upgrade가 포함된다. 독립 코드 검수에서 발견한 SMTP 수락 후 연결 정리 문제도 수정·검증했다.

실제 SMTP 인증·발신 도메인·메일 도착·스팸 분류, 배포 설정은 아직 확인하지 않았다.
