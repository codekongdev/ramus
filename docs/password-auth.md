# 비밀번호 회원가입과 실제 모델 확인

2026-11-10 사용자 지시로 기본 인증을 이메일 코드에서 이메일·비밀번호로 전환했다.

## 제품 흐름

- 회원가입: 이메일·닉네임·비밀번호·비밀번호 확인. 가입 성공 시 자동 로그인하고 공동 샘플에 참여한다.
- 로그인: 이메일·비밀번호. 인증메일·SMTP 설정 없이 동작한다.
- 비밀번호: 12~128자, 공백·Unicode 보존. scrypt와 무작위 salt로 저장하며 응답·로그·멱등 receipt에 원문을 남기지 않는다.
- 로그인과 가입의 이메일·IP별 시도 상한 및 같은 요청의 세션 재발급 상한을 적용한다.
- 폼 전환·성공·로그아웃·세션 만료 시 클라이언트의 비밀번호를 폐기한다. 비밀번호 관리자와 붙여넣기를 허용한다.
- 기존 이메일 코드 API는 기본 410이다. 이전 흐름이 필요할 때만 `RAMUS_EMAIL_CODE_AUTH_ENABLED=true`로 명시적으로 활성화한다. 운영 SMTP는 이 선택적 흐름에서만 필요하며 기본 제품 화면은 사용하지 않는다.

`e76b29da0414` 마이그레이션이 `account.password_hash`를 추가한다. 기존 계정·세션·프로젝트·AI 연결은 보존한다. 비밀번호가 없는 기존 이메일 계정을 새 가입으로 가져갈 수 없으며 중복 가입은 409, 비밀번호 로그인은 일반화한 401이다.

## 기존 로그인 계정의 초기 설정

로그인된 기존 계정은 헤더의 **비밀번호 설정**에서 새 비밀번호·확인을 입력한다. 성공 후에도 같은 계정과 세션을 사용하며, 다음 로그인부터 이메일·비밀번호를 사용한다. 비밀번호가 있는 계정에는 설정 버튼을 표시하지 않는다.

- `GET /api/me/password`: 활성 세션 본인 계정의 `{configured: boolean}`만 반환한다.
- `PUT /api/me/password`: 비밀번호와 멱등 키만 받고 이메일·계정 ID는 입력받지 않는다. hash가 null일 때만 조건부로 설정하며 이미 설정된 경우 `PASSWORD_ALREADY_SET` 409다.
- 변경 트랜잭션에서 세션 행을 잠그고 소유 계정·폐기·만료를 다시 확인한다. KDF 계산 중 로그아웃되거나 만료된 세션도 차단한다.
- 같은 세션·키·본문 재시도는 성공 결과를 재생하며, 다른 본문은 멱등 충돌이다. 다른 세션의 receipt를 재사용하지 않는다. 재생 응답 전에도 세션을 확인한다.
- 기존 계정 ID·닉네임·프로젝트·AI 연결을 유지한다. 닫기·성공·로그아웃·만료 시 입력 암호를 폐기한다.

로그인 세션이 없는 기존 계정의 복구와 비밀번호 분실·변경은 별도 범위다.

개발 머신의 기본 DB는 이 저장소에 없는 마이그레이션 이력을 사용하고 있어 변경하지 않았다. 대신 이 작업 폴더 전용 개발 DB를 생성해 `head`와 가상 샘플을 적용하고 서버를 실행했다. 로컬 `.env`의 인증·암호화 비밀값은 Git에서 제외한다. 운영 DB와 배포 환경에는 아직 적용하지 않았다.

## 자동 검증

- `pnpm verify --only web,i18n`: 타입·문구 검사와 웹 532개 테스트 통과. `pnpm --filter @ramus/web build`도 통과했으며 375px 가입·초기 설정 양식을 확인했다.
- API 단위 738개, Ruff, OpenAPI·생성 타입·검증 스크립트 검사 통과. 전체 PostgreSQL 통합 실행은 325개 통과·1개 실패·teardown 오류 2건이었다. 세 건 모두 동일 앱의 lifespan을 여러 이벤트 루프에서 시작하던 테스트 구성 문제로 재현했고, 한 번만 시작하도록 수정한 뒤 영향받은 세 파일 30개를 재실행해 통과했다. 전체 통합 명령을 다시 실행하지는 않았다.
- 전체 E2E는 41개 통과·초기 설정 테스트 1개 실패였다. 불일치 안내와 전체 오류 안내 두 요소를 하나로 찾던 테스트 선택자를 구체화한 뒤 초기 설정 시나리오를 재실행해 통과했다. 가입·재로그인·실패 후 재시도·세 계정·기존 계정 초기 설정·전체 MVP의 42개 시나리오를 확인했다. 새 상태 API 응답은 기존 화면 모의 테스트에도 추가했다.
- 실제 개발 서버의 로그인 화면·health 200, 익명 초기 설정 조회 401, 기본 비활성 이메일 코드 요청 410을 확인했다. 실제 메일과 모델 호출은 이 초기 설정 검증에 사용하지 않았다.
- OpenAPI와 생성 타입을 갱신했다. 기존 기능의 E2E 계정 준비도 이메일 코드 대신 제품 회원가입 화면을 사용한다.
- 독립 검수에서 SMTP 선택 사항 전환으로 빠졌던 운영 고정 인증 비밀값 검사를 복원했다. 운영에서는 SMTP 사용 여부와 관계없이 안정적인 `RAMUS_AUTH_SECRET`가 필요하다.

## 실제 모델 확인

이전 Ramus 프로젝트의 로컬 설정에서 기존 OpenAI 키를 찾고 값은 출력하거나 저장하지 않았다. 현재 설정된 `gpt-6-luna`로 실제 제공자를 호출했다. 기존 데이터와 분리한 `ramus_test_live_*` DB를 만들고 검증 후 삭제했으며 실제 메일은 발송하지 않았다.

확인한 동작:

1. 인증메일 없이 비밀번호 회원가입.
2. 계정 키 암호화 연결과 모델 접근 확인.
3. 적용한 자료에만 들어 있는 표식을 실제 응답에서 확인.
4. 두 독립 업무의 자동 분기·자식 완료와 자료 버전 초기 상속.
5. 실제 모델 정리 생성, 사용자가 편집한 본문 승인·버전 저장.
6. 공유된 승인 결론의 표식을 다음 실제 AI 응답에서 확인.
7. 결론에서 새 대화를 만들 때 정확한 승인 버전 입력 유지.

품질 한계도 확인했다. 실제 정리 생성은 완료됐지만 자료의 검증용 표식을 결론에 유지하라는 지침은 생략됐다. 첫 점검은 이 엄격한 표식 조건에서 중단됐으며, 후속 점검은 이 관측을 별도로 기록하고 제품이 지원하는 사용자 편집·승인으로 표식을 명시해 공유 흐름을 확인했다. 따라서 정리 출력의 지침 준수 품질까지 통과했다고 해석하지 않는다. 장문 정리 품질 평가와 분기 전체 평가 세트, 운영 배포·다중 실제 사용자 리허설은 아직 별도 확인이다.
